# HDM 界面与文案规范

## 终端菜单

- 首页状态不超过两行，只展示项目版本、系统、桌面、DRM 连接、图形会话与 RustDesk 版本；不放快捷入口、操作建议或重复的系统介绍。
- 宽终端采用两列五行，窄终端一列；所有功能通过稳定的编号调用，不能因为显示标签变化而改变动作 ID。
- 菜单选项使用动词和对象，例如“管理桌面”“查询设备 ID”，不把兼容性说明、内部实现方法、更新通道或阶段状态拼在名称后面。
- 兼容性检查放在实际执行前；不可用操作明确告知原因，不声称已经成功。

## RustDesk 配置

- 在用户主动查看配置或草稿时，完整显示 ID 地址、中继地址与服务器公钥，便于逐字核对。
- 永久密码、令牌等认证秘密必须隐藏输入，不在日志中打印。
- 显示完整服务器公钥时提醒用户注意终端录屏和公开日志；文件存储继续使用受控权限。
- 区分已保存配置、后台加载配置、服务器注册和远程画面连接状态。

## 安装与升级

- 安装管理器完成后，交互终端自动打开 HDM；非交互环境不启动菜单。
- 终端默认只展示进度和结果，详细的包管理器信息写入受权限保护的日志。
- 公开提交和 Release 只写用户可感知的实际改进，不重复版本标题，不出现内部发布方式。
- README 使用中文首页、英文次级文档；不使用重复的阶段性质提示充当功能说明。重要的系统限制应明确而具体地写出。
