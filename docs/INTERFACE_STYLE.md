# HDM 终端界面与文案规范

## 菜单展示

- 参考成熟服务器管理面板的紧凑文字菜单：统一横线、简短版本/系统状态区、编号明确，不额外绘制复杂框架。
- 主菜单使用 **8 个编号**：1–7 必须与七节点状态图逐一对应，8 专门管理 HDM 脚本、日志、诊断和智能部署。所有历史动作须通过显式映射保持可用。
- 宽终端两列四行；窄终端一列。标题行显示 `HDM v版本号`、Ubuntu 版本、架构，首页一行显示桌面、DRM、图形会话和 RustDesk 版本。
- 子菜单采用相同的标题和分隔线，编号左对齐；`0` 返回，`q` 退出；输入提示统一为 `请选择 >`。
- 不显示多余的“快速入口”“预览提示”或重复说明。系统风险在**执行高风险动作之前**展示，而非放在每个菜单标题中。
- 确认/报错必须给出实际动作及结果；仅成功调用系统命令不等于图形会话成功或远端画面可用。
- 只在交互式终端清屏；非交互测试/日志输出不得包含无意义 ANSI 清屏字符。

## RustDesk 配置

- 用户主动查看草稿或已保存配置时，完整展示 ID 地址、中继地址和公钥以供逐项校对；身份密钥、访问密码不能泄露到操作日志。
- 区分“配置已写入”“系统服务已运行”“服务器注册”和“远端画面验证”。

## 安装、测试、发布

- 管理器安装后只在交互终端自动进入菜单；非交互运行不阻塞。
- 前台保留步骤结果，完整 APT/系统失败记录以受限权限保存。
- Git 提交标题以 HDM 版本号开头，真实描述代码变更；Release 标题只显示一次，正文不得重复标题或发布流程。
- README 按 [Jiuliu README Style](https://github.com/nljie1103/jiuliu-readme-style) 的最新版规范排版。中文优先，英文辅助，必须明确 Ubuntu 26 GNOME Wayland 登录前与锁屏的**不同**验证边界。

- 根据协议提供实用推荐：Ubuntu 26 GNOME Wayland-only 场景的推荐安装可以采用 XFCE / X11 / LightDM，但不得自动删除 GNOME 或宣称无人值守已验证。

## 七节点实时桌面链路（v4.2.0）

主菜单版本头下方绘制一条横向状态数轴；节点依次为显示输出、登录管理器、图形协议、活动桌面、用户会话、RustDesk、设备 ID。按终端宽度自动选择完整横排、分段横排或纵排。绿/红/黄分别表示本地通过、明确异常、状态待核实；颜色不等于远控已完成验收。版本、实际分辨率及路径按能确认的真实值显示，不能从预设值推断当前屏幕。完整路径由 `--chain` 展示。

## 八阶段菜单路由（v4.3.0）

用户看到的编号由 `ui/menus.tsv` 定义；执行目标只从 `ui/menu-targets.tsv` 的静态映射加载。v4.2 的旧动作清单冻结于 `ui/legacy-menus.tsv`，既有代码保留在 `ui/actions.sh`；新增的脚本安全卸载与登录管理器操作在 `ui/actions_v2.sh`。菜单重构不得靠改变旧动作 ID 来破坏原有测试。菜单清单按 `scripts/build-menus-v2.py` 生成并在 CI 中验证。

## 日常操作最短路径（v4.4.0）

菜单 2、4、6 的常用安装/卸载/更新不单列预览和真实两个步骤，APT 依赖模拟属于卸载内部动作。卸载可在旧图形桌面仍在运行时进行，一次确认即可，程序只在发现 SSH、RustDesk、Xorg、systemd 等受保护包将被意外删除时拦截；提示图形通道可能中断，要求保留独立控制台。菜单 `8 → 1` 是唯一日常 HDM 更新入口，固定为最新正式 Release；指定版本/main/回滚等位于高级维护。既有动作清单继续使用静态映射完整保留。

## v4.5.0 快捷菜单与操作确认

八主阶段不变，常用安装、卸载、更新、状态直接位于对应模块第一层，重复或历史入口归入高级工具。登录管理器和桌面卸载只在内部做 APT 模拟，前台显示受影响的包后询问单次数字选择：1=remove 保留配置、2=purge 删除包管理配置、0/q=取消；两种模式保护 SSH/RustDesk/Xorg/系统核心组件。子菜单 0/q 返回上一级，根菜单 0/q 退出，Q 任意页面立即退出。
