# HDM v4.5.0 · 精简菜单使用指南

HDM 保留八个主模块（与桌面链路七节点及脚本管理对应），**常用操作直接在模块第一层**。安装、卸载、更新不必反复进入“预览”“真实操作”“选择版本”等重复菜单；深入的诊断、历史包和个别配置集中在「高级工具」。

## 八个主模块

| 模块 | 常用入口 |
|---|---|
| **1 显示输出** | 1 安装 Xorg Dummy、2 安装 Xvfb、3 启用 VKMS、4 状态、5 删除 Dummy 配置、6 分辨率、7 高级 |
| **2 登录管理器** | 1 安装 GDM3、2 安装 LightDM、**3 卸载 GDM3、4 卸载 LightDM**、5 更新、6 状态、7 切换、8 高级 |
| **3 图形协议** | 1 当前协议、2 Xorg/Xvfb 检查、3 结构说明、4 高级 |
| **4 桌面环境** | **1 安装 XFCE + Xorg + LightDM**、2 GNOME、3 MATE、**4 卸载 GNOME**、5 卸载 XFCE、6 卸载 MATE、7 更新、8 状态、9 切换、10 高级 |
| **5 图形会话** | 1 查看会话、2 分辨率、3 修复、4 高级 |
| **6 RustDesk** | 1 安装、2 卸载、3 更新、4 ID/中继/Key 配置、5 设备 ID、6 诊断、7 高级 |
| **7 设备信息** | 1 设备 ID、2 注册状态、3 系统/内核/架构、4 高级 |
| **8 HDM 脚本** | **1 最新正式版更新**、2 卸载 HDM、3 导出诊断包、4 安装日志、5 更新记录、6 系统检查、7 高级 |

高级工具保留原先所有 **381 个不同的底层动作**，不会因为精简展示而突然失去原有诊断、恢复或版本管理能力。

## 卸载：一层入口、一次选择

例如，从首页按 **`2 → 3` 卸载 GDM3**，会显示 APT 准备删除的软件包，随后看到：

```text
1. 卸载软件，保留配置（APT remove）
2. 卸载软件，同时清除配置（APT purge）
0/q. 取消返回
请选择 >
```

- **选 1**：执行真正的 `apt-get remove -y`，保留软件包配置。
- **选 2**：执行真正的 `apt-get purge -y`，清除 APT 管理的软件包系统配置。不会因此自动擦除用户主目录及个人数据。
- **选 0/q**：取消卸载，不执行 APT 删除，返回管理菜单。**不会删除 HDM 脚本。**

APT 的删除计划和受保护依赖检查在程序内部执行。对 `remove` 和 `purge` 分别校验，检测到会连带删除 RustDesk、SSH、Xorg 或系统基础包会拒绝操作。不会运行 `apt autoremove`，不会自动重启，也不会增加第二次 `y/N` 确认。

## 如何返回或退出

| 按键 | 子菜单 | 主菜单 |
|---|---|---|
| `0` | 返回上一级 | 退出 HDM |
| `q`（小写） | **返回上一级** | 退出 HDM |
| `Q`（大写） | 直接退出 HDM | 直接退出 HDM |

取消卸载与退出程序是两回事。没有选择删除模式，包管理器不会执行修改。

## Ubuntu 26.04 ARM64：从 GNOME/GDM3 改为 XFCE/LightDM

允许使用**先卸载旧组件、再安装新组件**的顺序：

1. 在独立 **SSH/云控制台**内打开 `sudo hdm`，准备系统快照。
2. `2 → 3` 卸载 GDM3，选择保留配置 `1` 或清除软件包配置 `2`。
3. `4 → 4` 卸载 GNOME，选择 `1` 或 `2`。
4. `4 → 1` 安装 XFCE、Xorg、LightDM 及 GTK 登录界面。
5. 必要时 `2 → 7 → 1` 选择 LightDM 为默认登录管理器，安排受控重启。
6. 用 `sudo hdm --chain` 检查本机链路，并从另一台机器实际测试 RustDesk。

如果不想有图形空档，也允许先装新的，再卸载旧的。**卸载正在运行的 GDM/GNOME 可能立即切断 RustDesk 显示，因此不能依赖同一 RustDesk 会话进行修复**。HDM 不会声称 Ubuntu 26 ARM64 无屏无人值守已经完成端到端验收。

## 解决升级后 `sudo hdm` 找不到命令

v4.4.0 等旧版更新器在严格 root 权限环境中可能将安装的源码目录设置为 700、脚本设置为 600；这与在卸载菜单按 `q` **没有直接关系**。请从 SSH/云控制台执行：

```bash
sudo chmod -R a+rX "$(sudo readlink -f /opt/hdm/current)" && sudo chmod 755 /opt/hdm/current/hdm.sh && sudo hdm
```

若命令入口仍有问题，可先运行 `sudo bash /opt/hdm/current/hdm.sh` 访问菜单，再检查 `/usr/local/bin/hdm` 的实际链接。当前新版更新器会在原子切换前修复源码权限。

v4.4.0/v4.4.1 还曾有菜单编号 `8.1` 与 `8.10` 比较冲突；可以从旧版高级菜单找到正式更新入口。v4.4.2 及之后的 `8 → 1` 已改为正常直接更新。
