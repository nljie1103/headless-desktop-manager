# HDM v4.3.1 · 八阶段菜单使用指南

HDM 将**七节点桌面链路**直接映射为主菜单 **1–7**，另由 **8** 管理 HDM 自身的更新、卸载、日志、诊断与智能部署。终端足够宽时使用双列，窄终端使用单列；选项编号以当前菜单为准。

## 主菜单

```text
  HDM v4.3.1 · ubuntu 24.04 / x86_64

  显示输出 ─ 登录管理器 ─ 图形协议 ─ 桌面环境
              ↓ 图形会话 ─ RustDesk ─ 设备 ID

  1. 显示输出管理                    5. 图形会话管理
  2. 登录管理器管理                  6. RustDesk 管理
  3. 图形协议管理                    7. 设备 ID 与设备信息
  4. 桌面环境管理                    8. HDM 脚本管理

  0 / q 退出
```

*上方是精简的文字示意，程序实际显示绿色/红色/黄色节点、当前版本及分辨率。* `0` 返回上一级，`q` 退出；根菜单 `0` 也退出。查看完整树：`hdm --menu-tree`。

## 每个阶段管理什么

| 一级菜单 | 主要子菜单（安装 / 卸载 / 更新尽量靠前） | 注意事项 |
|---|---|---|
| **1 显示输出管理** | 安装 Dummy/Xvfb/VKMS、卸载/清理、更新、分辨率、切换、状态、恢复 | 安装了 Dummy 不等于输出已经建立；必要时保留定时恢复 |
| **2 登录管理器管理** | 安装 GDM3/LightDM、卸载预览和真实卸载、更新、状态与配置、服务、日志 | 登录管理器负责认证和启动桌面会话，不是显示器；真正卸载需新管理器运行及用户确认 |
| **3 图形协议管理** | X11/Wayland 状态、Xorg、Wayland/Portal、兼容诊断 | Xorg 是常见 X11 服务器，Ubuntu 26 GNOME 不能强制切回 GNOME Xorg |
| **4 桌面环境管理** | 安装 GNOME/XFCE/MATE、卸载预览和真实卸载、更新、切换、状态、对比、修复 | 保留现有桌面，不因安装另一桌面而自动删除旧桌面 |
| **5 图形会话管理** | 查看会话、DISPLAY/分辨率、D-Bus、锁屏、会话修复 | 登录管理器运行不等于有已登录用户会话 |
| **6 RustDesk 管理** | 安装、卸载、更新、配置 ID/中继/Key、服务诊断 | 密码权限与远端连接需要额外验证 |
| **7 设备 ID 与设备信息** | 查看/管理设备 ID、系统内核架构、RustDesk 版本、网络 | 读取到 ID 只代表本地可查询，不等于公网连通 |
| **8 HDM 脚本管理** | 更新脚本、卸载脚本、查看更新日志、安装日志、快速导出日志、诊断、智能安装、备份 | 卸载管理器保留历史版本和用户数据，不影响桌面或 RustDesk |

## 常用导航

- `6 → 安装 → 自动安装推荐版本 → 安装并检查服务`：安装 RustDesk 并执行本地检查。
- `6 → 配置 ID / 中继 / Key → 配置自建服务器`：填写、预览、保存及读回配置。
- `7 → 查看设备 ID`：查询 ID 与可能的注册状态；`7 → 系统 / 内核 / 架构`：主机信息。
- `8 → 更新脚本`：检查 Release、安装或回滚 HDM。
- `8 → 卸载脚本 → 预览卸载范围`：查看将要删除的入口和保留文件。
- `8 → 卸载脚本 → 卸载 HDM（保留配置与日志）`：经用户确认后移除 `/usr/local/bin/hdm` 与 `/opt/hdm/current` 的 HDM 自建链接。**不会**移除旧版本目录、`/etc/hdm`、`/var/lib/hdm`、`/var/log/hdm`、GNOME、XFCE、LightDM 或 RustDesk。
- `8 → 快速导出全部日志`：导出可取得的日志与诊断包，分享前须审阅脱敏效果。
- `8 → 智能安装与续装`：按主机协议和现有软件生成推荐计划，再选择执行。

## 为什么保留兼容映射

v4.2.0 之前的动作编号已经有真实实现和回归测试，例如 RustDesk 配置、显示快照、安装恢复等。v4.3.1 并不通过文本替换把它们强行改成新编号，而是使用以下文件映射：

```text
ui/menus.tsv           # 新的八阶段导航结构
ui/menu-targets.tsv    # 新叶子菜单编号 → 旧动作 ID / 新增动作
ui/legacy-menus.tsv    # 保留的旧菜单动作元数据
ui/actions.sh          # 既有 381 个动作实现与路由
ui/actions_v2.sh       # 新增管理动作与安全卸载
```

改动菜单需要更新 `scripts/build-menus-v2.py`，并运行 `bash tests/run.sh`。映射检查保证所有旧动作仍有入口、没有无效或重复路由。当前新树有 578 个条目、426 个可选择叶子，覆盖此前 381 个不同的底层动作。**有入口不表示所有操作均已通过目标机端到端验收。**

## v4.3.1：真实卸载与 GNOME → XFCE 迁移

此前 `2 → 2 → 1` 只有卸载模拟。现在 **保留预览，并且新增实际卸载入口**：

| 菜单路径 | 功能 | 是否改动系统 |
|---|---|---|
| `2 → 2 → 1` | 预览 GDM3 的 APT 删除范围 | 否 |
| `2 → 2 → 2` | 真正卸载 GDM3 | 满足替代 LightDM 条件并确认后，会执行 APT remove |
| `2 → 2 → 3` | 预览 LightDM 删除范围 | 否 |
| `2 → 2 → 4` | 真正卸载 LightDM | 满足替代 GDM3 条件并确认后执行 |
| `2 → 5 → 1` | 通过系统选择界面设置默认 LightDM | 修改默认管理器选择，不会自动重启 |
| `2 → 5 → 2` | 设置默认 GDM3 | 修改默认管理器选择，不会自动重启 |
| `4 → 2 → 2` | 真正卸载 GNOME | 替代 LightDM/XFCE 正常、无活动 GNOME 后执行 |
| `4 → 2 → 3/4` | 真正卸载 XFCE/MATE | 需存在其他桌面、无待卸载的活动用户会话 |

建议迁移顺序：**安装 XFCE + Xorg + LightDM → 选择 LightDM → SSH/控制台保护下重启 → 测试登录界面、XFCE 及 RustDesk → APT 预览 → 真正卸载 GDM3 → 真正卸载 GNOME**。不会替用户自动重启，也不会自动卸载关联配置或执行 `apt autoremove`。卸载前检查软件包的实际删除集合，意外包含 SSH、RustDesk、Xorg 或替代桌面会拒绝执行。
